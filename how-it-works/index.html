Architecture

How Svalin works

Svalin provides OS-level visibility and cryptographic proof for AI-native workflows.

A lightweight agent deployed through your MDM wraps supported AI coding tools at the MCP and LLM proxy layer — capturing every tool call, attributing every session by process, and sealing every event into a tamper-evident chain before it leaves the device. No developer action required.

The Local Agent — The "Plumbing"

Zero-friction deployment, real-time process introspection

Svalin deploys as a lightweight Go binary via Jamf, Microsoft Intune, or Kandji. No developer action, no code changes, no manual configuration. Once enrolled, the agent starts watching immediately.

Native OS syscalls — no shelling out

Process tree analysis uses proc_pidinfo on macOS — a direct kernel call. No spawning ps, no ptrace. Lower overhead, no side-effects, no race conditions from external process invocations.

500ms polling cycle, negligible CPU overhead

Configuration integrity monitoring runs on a 500ms cycle — fast enough to catch tampering in real time, light enough to be invisible to the developer and not appear in performance profiling.

Auto-detection of supported agents

On enrolment, the agent identifies Claude Code, Claude Desktop, Cursor, and Gemini CLI and configures itself without touching the developer's workflow. Sub-day rollout for existing MDM fleets.

2

Policy Enforcement — The "Logic"

Two interception layers, applied before data moves

Governance happens at two distinct points in the AI workflow — before tool calls execute, and before prompts leave the machine. Both layers are configured automatically via MDM. Neither requires developer cooperation.

The MCP Layer

Svalin wraps each Model Context Protocol server, intercepting tool calls before they execute. Every file read, shell command, and external API call is policy-checked first. Approved operations proceed transparently. Blocked or redacted operations are logged as policy events.

The LLM Proxy

Every request to Claude, Gemini, or local models is intercepted on-device. PII and credentials are detected against configured patterns and redacted locally before the prompt leaves the machine. No sensitive data reaches the model provider unreviewed.

What gets captured

File reads and writes
Shell command invocations
LLM interaction when supported

Developer and device attribution
Timestamps and sequence numbers

Configuration integrity — bypass attempts detected, not just logged

The 500ms monitoring cycle watches agent configuration files for tampering. If the LLM proxy URL is changed, an unapproved MCP server is added, or a hook is suppressed — the correct configuration is automatically re-applied and a compliance alert is raised with device identity and timestamp.

What triggers an alert

LLM proxy URL changed · Unapproved MCP server added · Hook suppression detected · Agent configuration file modified · Svalin agent process terminated

What happens on detection

Correct configuration automatically re-applied · Compliance alert raised on platform with device identity and timestamp · Event logged in tamper-evident chain as a policy violation

The Audit Trail — The "Proof"

Cryptographic chaining from device to compliance report

Every event captured by Svalin is signed on-device with a per-device Ed25519 key, then hashed into a chain. Modifying any event — or inserting a gap — breaks the chain. The result is a tamper-evident record that proves log integrity and ordering, not just that events were stored.

Cryptographic Chaining

  • Per-device Ed25519 signing key generated at enrolment
  • Each event signed and hashed into the chain before leaving the device
  • Sequence numbers and heartbeats make gaps visible, not invisible
  • Append-only EU-hosted backend with separate key management

Compliance Ready

Audit data is structured to support evidence generation mapped to:

  • ISO 42001 — AI management system monitoring (Cl. 9.1)
  • SOC 2 — access control and data restriction (CC6.1, CC6.6)
  • EU AI Act — record-keeping and transparency (Art. 12, 13)
  • GDPR — records of processing activities (Art. 30)

A tamper-evident log proves integrity of what was captured. The heartbeat and sequence number system helps auditors identify periods where nothing was captured — so gaps are visible rather than invisible. Both matter for a credible compliance posture.

Coverage Scope

What Svalin governs — and what it doesn't

Svalin governs enrolled devices running supported agents. Knowing the boundary of coverage is part of governance.

In scope

  • Enrolled MDM devices
  • Claude Code and Claude Desktop
  • Cursor
  • Gemini CLI
  • MCP tool calls across supported agents

Surfaced as gaps

  • Unmanaged / personal devices
  • Web browser AI usage (ChatGPT, Claude.ai, etc.)
  • Remote dev boxes and cloud IDEs
  • Copy-paste workflows
  • Unsupported agents (outside Svalin's visibility)

Svalin's governance scope is explicit. What falls outside it is outside its visibility — and the platform makes no claim otherwise.
